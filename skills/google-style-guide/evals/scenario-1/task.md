# Technical Documentation Review and Rewrite

## Problem Description

Your company's technical writing team has flagged an internal database guide for revision before it is published in the public developer portal. The document, written by an engineer some time ago, covers database replication setup but does not meet the documentation standards now required for all public-facing content.

A senior editor has reviewed it and noted that the guide has a number of issues around voice, tone, terminology, and formatting that need addressing. The goal is to produce a polished revision that reads professionally and consistently, suitable for an international developer audience.

The original document is at `inputs/database_guide.md`.

## Output Specification

Produce the following files in your working directory:

1. `revised_doc.md` — the fully corrected version of the database guide, with all style issues resolved.
2. `review_notes.md` — a document that describes the review process you followed and the categories of changes you made. Organize your notes by the type of concern addressed (for example: voice and tense, headings and structure, formatting, language).

Do not alter the technical accuracy of the document — only its style and language.
